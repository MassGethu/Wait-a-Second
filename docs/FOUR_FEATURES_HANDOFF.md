# Wait a Second Android hackathon additions

## Baseline and scope

The starting Android checkout already contained the Kotlin accessibility service, a full-screen Instagram messaging check-in after ten minutes, Light mode retyping, Strict mode's ten-second reset, session statistics, and SQLite session history. The DM change below is an upgrade to that baseline. The counter, grayscale guide, and trusted contact setup are new to Android. The module has a minimum SDK of 24 and compiles and targets SDK 37.

## What was built

| Feature | Behavior and limits |
| --- | --- |
| Mindful DM prompts | During a focus session, a recognized Instagram conversation can show a non-modal banner after a five-second dwell. The banner shows the current goal and offers **Yes, it’s relevant**, **No, it’s personal**, and **Return to focus**. The first two choices leave messaging open and record the response with session metadata. The banner closes after twenty seconds or when navigation, keyboard use, or recognized composer surfaces take over. A ten-minute cooldown and thirty-second brief-exit grace apply to coarse Instagram conversation state. The app uses structural signals and does not identify individual conversations or read message text. |
| Doomscroll counter | The opt-in switch is in **Statistics → Doomscroll counter · Today**. It measures time in recognized Instagram Reels and YouTube Shorts viewers during and outside sessions. Statistics distinguish duration, episodes started, and detected forward or backward pager transitions. The first reported page is a baseline. Transitions can be missed when a build omits pager IDs or settled indices. An independently optional, touch-through timer shows the current episode. Full-screen interventions and calls suspend measurement and hide the timer. |
| System grayscale | **Home → Focus options → System grayscale** opens a guide and Android Accessibility settings. On devices with Grayscale in Color correction, the user can set up a system shortcut and restore their previous setting after a session. This is a device-wide, manual fallback. The app leaves the user's correction settings untouched. [Android Accessibility Help](https://support.google.com/accessibility/android/answer/11183305), [Android permissions reference](https://developer.android.com/reference/android/Manifest.permission#WRITE_SECURE_SETTINGS) |
| Trusted contact exceptions | **Home → Focus options → Trusted contact exceptions** opens the system picker and maintains local shortcuts to selected contacts. Open a card to star or unstar the contact. In Android Do Not Disturb or Modes, the user can allow calls from starred contacts and select message exceptions where available. Other Android favorites also qualify. Android owns the rules and applies them when the user turns on the relevant mode. Turning off the in-app setup hides the local list. Android settings control whether system exceptions remain active. During focus, Wait a Second dismisses its overlay for system call surfaces and supported ringing or in-call audio modes, and keeps the session running. [Android contact intents](https://developer.android.com/guide/components/intents-common#Contacts), [Android Do Not Disturb](https://support.google.com/android/answer/9069335), [Notification policy](https://developer.android.com/reference/android/app/NotificationManager.Policy) |

Selective grayscale, automatic DND changes, and per-contact WhatsApp filtering are deferred. The current Android target uses system DND rules, which can combine policies from several sources. The application uses the existing user-enabled accessibility service. The contact picker provides temporary access to the selected row. There are no new broad contact, notification-listener, phone-state, or policy permissions. The local list stores only a display label and a contact lookup URI. Both the database and focus options preferences are excluded from backup and device transfer. [Android 15 Do Not Disturb changes](https://developer.android.com/about/versions/15/behavior-changes-15#dnd-changes), [Android audio modes](https://developer.android.com/reference/android/media/AudioManager)

## Code map

- `DmDwellPolicy`, `SessionTracker`, `DistractionEvent`, `OverlayData`, and `AccessibilityOverlayController` manage prompt timing, actions, and history. `overlay_dm_checkin.xml` is a separate non-focusable window. `InstagramReelsDetector` distinguishes the inbox, conversations, and Reels.
- `WaitaSecondAccessibilityService` confirms viewer and foreground state, recognizes a settled pager signal, and stops tracking at a lock, a blocking intervention, a call, or service teardown. `AccessibilityNodeInspector` uses structural-only YouTube reads outside focus and structural Instagram reads without message text. `ShortVideoBadge` owns the optional timer window and updates once a second while attached.
- `ShortVideoTracker`, `ShortVideoRepository`, and `LocalSessionStore` accumulate monotonic durations. Schema 3 adds absolute totals by local date, platform, and session. Active visits checkpoint every thirty seconds without polling the target screen. An abrupt kill can lose the time since the last checkpoint. Restart begins a new observed episode and does not add time for the gap. The first day owns the episode start when viewing crosses midnight.
- `MainActivity`, `StatisticsPanel`, `screen_statistics.xml`, and `screen_home.xml` expose the counter and settings. `FocusOptionsActivity`, `TrustedContactStore`, `activity_focus_options.xml`, `row_trusted_contact.xml`, and `AndroidManifest.xml` provide the system guides and local contacts. `strings.xml` contains the new labels and instructions. `backup_rules.xml` and `data_extraction_rules.xml` keep focus options local.
- Future consumers can observe `ShortVideoRepository.state` for coarse foreground activity, active platform, an elapsed-time episode anchor, daily and session viewer totals, and transitions. `SessionManager.state` supplies the goal, session phase, active intervention, `mindfulPromptVisible`, and recent interruption and prompt outcomes.

## Demo and phone verification

Install `app/build/outputs/apk/debug/app-debug.apk` through Android Studio or `adb install -r app/build/outputs/apk/debug/app-debug.apk`. Open Home, choose **Enable monitoring**, and grant the existing activity detection service in Android Accessibility settings.

1. **Messaging.** In each focus mode, open Instagram's inbox and wait at least six seconds. Open a conversation and wait five to seven seconds with the keyboard closed. Expect the goal banner in the conversation only. Choose **No, it’s personal** and keep typing. Revisit the inbox and the chat immediately to confirm the cooldown. Use a new focus session to verify **Yes, it’s relevant** and **Return to focus** separately. Share a Reel in a chat and verify the preview does not trigger a Reels block. Open the actual Reels viewer to verify the existing intervention still appears.
2. **Counter.** With no focus session, turn tracking on in Statistics. Spend ten seconds in Reels and ten in Shorts. Swipe one page at a time and check that ordinary feed and DM time do not accrue. Check the separate platform totals, combined time, episodes, and detected transitions. On builds exposing the supported pager index, a forward or backward change should add one transition after the baseline. Optionally enable the small viewer timer, then verify it appears on the viewer without intercepting swipes. Start a focus session, repeat using Light mode, and verify the current-session subtotal excludes earlier use. Lock the screen for ten seconds during a viewer, switch apps, then force-stop and reopen Wait a Second. Totals should exclude the lock gap and survive reopening, subject to the checkpoint interval. If Android disables the service on force-stop, enable monitoring again from Home. Disable tracking and confirm the total stops changing.
3. **Grayscale.** Open the guide and verify the app switch leaves the display unchanged. In Android Settings choose **Grayscale** and enable the shortcut if available. Verify Instagram and YouTube appear grayscale, including when the app is backgrounded. Restore the previous correction state manually and verify ordinary colors return. Check behavior on the target OEM settings screen.
4. **Calls.** Pick a contact, verify the row remains after reopening the app, open its card and star it in Android Contacts. In DND allow starred callers, disable repeat-caller exceptions for the test, and turn on that mode. Call from a starred and a non-starred number. Android should apply the configured rules. Repeat the starred call with a focus intervention visible. The call UI should be accessible and the session should still be active afterward. Remove the row, verify the local list updates, and unstar or restore the Android policy if desired. Confirm the build requests no contact or notification access. WhatsApp follows the device's ordinary notification behavior.

## Automated checks

Run `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest :app:lintDebug`. JVM tests cover DM cooldown and actions, inbox/Reels separation, timestamp and local-day accounting, session splits, restarts, and deduplication. The instrumentation suite includes SQLite migration and idempotent persistence, opt-in settings, and existing focus, scheduling and retyping flows. Run `./gradlew :app:connectedDebugAndroidTest` against a test device for the Android suite.

The debug build and Android lint passed. All 133 JVM tests passed, including two checks that strip text and descriptions from captured Nord CE4 screens. Structural signals alone distinguish the Instagram conversation from the Reels viewer, and neither captured YouTube watch screen counts as Shorts. All 14 instrumentation tests passed on the Android 15 emulator with animations disabled. The additions and changes are in `DeviceSnapshotTest`, `PlanningAndDwellTest`, `ScreenClassifierTest`, `ShortVideoTrackerTest`, `LocalSessionStoreTest`, and `FeatureFlowTest`.

On the Android 15 emulator, the accessibility service recognized separate inbox, conversation, Reels, and Shorts fixture screens. The DM prompt displayed the goal, its personal response left the conversation open, and inbox navigation respected the cooldown. The compact banner left the fixture's navigation reachable. The counter separated Reels and Shorts, recorded one change per settled test index, and ended the viewing episode on screen lock. After Light mode retyping, the viewer timer allowed paging taps, disappeared on viewer exit, and the current-session subtotal remained separate from outside-focus time in Statistics and SQLite. Both totals survived force-stop and reopening. A simulated cellular call cleared the visible distraction overlay while the session stayed active.

Android Settings enabled Grayscale through Color correction and restored the display to color when switched off. The native Contacts picker saved the selected test contact's label and lookup URI. The app reopened its contact card and removed the local row on confirmation. With repeat callers disabled and Android Do Not Disturb set to starred callers, the emulator entered ringtone mode for the starred number and stayed in normal audio mode for an unstarred number. The test restored Do Not Disturb afterward.

The Instagram and YouTube fixtures exercise the actual accessibility service and overlay code with controlled view IDs and events. The Nord CE4 captures used by JVM tests provide additional Instagram structural coverage. The current Instagram and YouTube production apps, pager signals, and OEM call behavior still need the phone checks above.
